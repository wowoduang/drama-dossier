# Drama Dossier 升级路线

## v3.2：证据审核闭环
- JSON 单一事实源、稳定 ID、结构校验和审核历史。
- 本地 Web 证据审核台。
- FFmpeg 镜头切换候选；镜头切换不自动等于语义场景。

## v3.3：剧情理解 + 智能精彩剪辑
- 新增 `storylines` 和 `highlights`。
- 七维可解释精彩度评分与 `context_required`。
- 30 秒、60 秒、3 分钟、5 分钟剪辑预设。
- 剪映式本地工作台：视频、多轨时间轴、高光精修、序列生成、重排、连续预览和项目导出。
- `highlight_engine.py` 与 `render_project.py` 完成剪辑项目和 FFmpeg 硬切渲染。

## v3.4：多模态候选理解
- 镜头切换、RMS 音量峰值和持续低能量窗口抽取。
- 字幕/ASR 时间码线索、均匀关键帧和 JPG 联系表。
- 自动生成 ChatGPT 视觉审核提示和结构化输出格式。
- `import_ai_review.py` 将视觉观察导入为 `VIS` 证据、事件候选导入为 `UNREVIEWED`。
- `arc_candidates.py` 结合已有事件、剧情线和直接因果边提出 setup / peak / reaction / payoff。
- 人工审核台可导入 AI 视觉审核 JSON；剪辑工作台显示音画 cue 与弧线段落。
- 修正评分：音量峰值和镜头数量不再自动增加情绪/视觉/剧情重要性。

## v3.5：全剧记忆引擎（已实现）
- `batch_media_scan.py` 批量预扫描整季原片，SHA-256 断点续跑。
- SQLite Series Memory Engine：分集档案投影、全剧人物实体、事件时间线、关系历史、剧情线和伏笔线索。
- 跨集人物/剧情线/伏笔候选只提示，不自动合并；人工确认/驳回写审计。
- 按内容哈希跳过未变化档案；变化覆盖需显式确认。
- 导出全剧记忆 JSON、证据时间码索引与只读 Series Dashboard。

## v3.6：跨集剪辑编译器（已实现）
- `series_compiler.py`：按全剧人物、双人物关系、剧情线、伏笔或词面查询生成跨集多源剪辑项目。
- 默认只纳入审核通过的实际事件；目标时长按完整片段筛选，不切短事件凑时长。
- `render_series_project.py`：多源 FFmpeg 渲染，统一视频/音频技术规格，无音轨片段补静音。
- `web/series-workbench.html`：跨集预览、入出点精修、片段排序和项目导出。
- 每个剪辑片段保留 episode/source/time/event/highlight/evidence provenance。

## v3.7：跨集故事弧与认知差异编译（已实现）
- 将 ChatGPT 生成的叙事计划编译为可追溯的跨集剪辑工程；每段有叙事角色、事件 ID、证据引用和选择理由。
- `make-prompt` 将人物/关系选择扩展到已审核剧情线上下文，并附带因果邻居、伏笔、故事弧、关系历史和认知状态。
- `story-arc-workbench.html` 支持逐段审核、理由记录、顺序调整和计划导出。
- 编译器检查事件/证据归属、原片顺序、连续性连接、因果审核、缺失叙事角色和风险标记。
- 每段剪辑附加人物/观众认知快照与信息差风险，禁止未来认知倒灌。
- 分集档案被替换后，相关已通过跨集因果边自动重开审核。

## 后续 v3.8：语义检索与剧透控制
1. 基于事件描述/对白/证据观察的向量与关键词混合检索。
2. 按观看进度控制剧透边界，区分“已播出集数”和“全剧知识”。
3. 重复镜头/近似场景检测，辅助避免跨集剪辑重复画面。
4. 对代理文件、缩略图缓存、代理素材与原片时间码映射进行管理。
5. 以真实用户剪辑反馈校准推荐，不把播放量/音量当作剧情真值。

## 不应自动化为事实
- 不把人脸相似度直接当身份事实。
- 不把 ASR 的说话人猜测当角色身份。
- 不让音量或快切直接决定情绪和剧情价值。
- 不把时间先后直接当因果。
- 不自动把后续揭示写回前期角色认知。
- 不为了凑目标时长强行截断语义完整片段。
