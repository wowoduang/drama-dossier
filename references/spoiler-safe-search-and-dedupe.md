# v3.8 剧透安全检索与重复素材审核

## 目标

允许用户按“我看到第 N 集”为边界检索全剧素材，同时避免后续揭晓的信息通过人物合并、别名、剧情线摘要或因果边泄露。检索结果是候选材料，不是新的事实结论。

## 检索边界

- `--as-of` 必填；接受已入库 episode_id 或集数。
- 文档只从 `episode_number <= cutoff` 的分集档案构建。
- 人物名/别名使用当前分集本地提及，不把全剧 global character aliases 反向注入早期集。
- 剧情线和伏笔使用分集 mention，不使用可能含有后续揭晓的全剧聚合描述。
- 角色认知记录只取截止集内、审核通过、按 playback_time 排序的记录；普通观众视角不包含角色私有认知。
- 默认只检索 PASS 对象；未审核对象必须显式启用，且输出不得作为发布事实。
- 未来集数只报告隔离数量，不向结果、扩展提示或 UI 暴露未来 episode_id 和内容。

## 语义扩展

本地召回使用 BM25、中文字符 n-gram、短语匹配和保守词典。`make-expansion-prompt` 只将截止集范围内的候选结果交给 ChatGPT 生成同义词。扩展词只能改变召回，不可作为事实证据；ChatGPT 不得从训练记忆或用户暗示中补充截止集后的剧情。

当前没有向量数据库或 embedding 模型；如未来引入向量索引，必须把索引按 episode visibility partition，或在向量召回后再次执行严格 episode/visibility 过滤。仅靠提示词不构成剧透隔离。

## 跨集可见性声明

全剧身份合并不等于观众已知身份。使用 `series_visibility.py` 声明实体的 `effective_episode_number`，证据必须存在、属于该实体且不晚于声明集。没有 PASS 声明时，严格剧透模式不得用该跨集关联做身份推理。声明更改写入 `visibility_audit`。

## 重复素材检测

`dedupe_clips.py` 综合：

1. 同一源文件时间区间重叠；
2. 每个片段多个采样点的 64-bit grayscale dHash；
3. 标题、理由、动作和台词的中文 n-gram 相似度。

相似镜头可能是闪回、回放、呼应、反打或故意重复。检测器只写候选，不自动移除素材。人工审核后导出 edit-project 副本，原始 dossier 和 Series DB 不变。

## 已知限制

- BM25/n-gram 不是深度语义向量检索；对隐喻、长距离语义和同义改写的召回有限。
- 同名角色、化名、易容、替身和旁白身份必须通过人工身份审核。
- 观众可见时间依赖人工维护的证据声明；没有证据时按未知处理。
- dHash 对裁切、字幕叠加、镜像、调色和速度变化敏感；也可能对相似构图产生误报。
- 检测报告不能判断重复镜头在叙事上是否应该保留。
